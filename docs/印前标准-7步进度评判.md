# 印前 7 步标准 · 进度评判（对照 V0.8）

> 评判对象：`色彩工坊` V0.8（FastAPI + 原生前端，ΔE/CIEDE2000 为核心的印前色彩管理闭环平台）
> 评判基准：现代印刷工厂印前 7 步标准流程
> 核校日期：2026-11-18（结论经代码逐项核对，锚点行号对应当前工作区）
>
> **实施进展（同日）**：P0 四项全部落地——P0-1（预检深水区）、P0-2（PDF/X-4 结构封装）、
> P0-3（签样状态机 / 放行门禁）、P0-4（显示器档案 / 软打样门禁），见
> [V0.9-P0-实施记录](V0.9-P0-实施记录.md)；第 1 步 ~65%，第 2 步 ~50%，第 4 步 ~45%，
> 第 5 步 ~55%，第 6 步 ~60%。显示器物理校准仍需外部硬件，软件做档案、门禁与
> 测量数据接收（CGATS/TSV 导入、白点/对比度推导、原样留档导出）。

## 1. 评判口径

印前标准描述的是**含物理设备的完整产线**。其中制版（CTP）、实物硬打样、真机印刷依赖硬件，
不是软件缺陷。因此本评判把缺口分两类算账：

| 类别 | 含义 | 评判方式 |
|---|---|---|
| **软件项** | 纯代码即可实现（预检、PDF/X、显示器链路、拼版、签样、打包） | 计入进度，作为应补缺口 |
| **环境绑定项** | 依赖 CTP/打样机/印刷机/测量硬件 | 不计软件进度；只评估「软件为其产出的标准化数据与文件是否就位」 |

## 2. 总评

项目在**色彩可控 + 数据可追溯**上做得深、做得诚实：预测 → 实测 → 补偿 → 校准 → 收敛的数据
闭环扎实，测量方法学门禁与精度基线门禁在同规模项目中少见。

它**不是、也不应被要求成为**一条含 CTP 的完整物理产线。正确的定位是：
**印前色彩数据与标准化平台**——数据链核心已覆盖，并为下游制版/打样/签样产出了标准化数据；
真正值得补的软件缺口集中在**上游文件预检深水区、PDF/X 标准化输出、显示器校准链路、
拼版与签样工作流**，而不是继续加深已有的色彩数据闭环。

## 3. 结论表

| 环节 | 进度 | 类型 | 一句话 |
|---|---|---|---|
| 1 文件接收与预检 | ~65%（V0.9 P0 后） | 软件项 | 图像侧扎实，PDF 侧补齐字体/出血/有效 DPI/开本 |

## 4. 逐环节

### 4.1 文件接收与预检 —— 部分达成（图像侧扎实，PDF 侧浅）

**已做**（`app/services/files.py`）
- 图像：嵌入 ICC 解析（:39-56）、DPI < 300 告警（:60-66）、模式/尺寸/主导色。
- PDF：页数与首页缩略图（:111-142）、CMYK/RGB 图像判定（:221-226）、输出意图
  `/OutputIntents`（:203-219）、专色 `/Separation` 检测（:181-186）、透明度 SMask（:192-194,
  :232-236）、跨页尺寸一致性告警（:237-242）。
- 状态分级 pass/warn/error（:244-246）。

**缺失**（V0.9 P0 已补：字体真嵌入、TrimBox/BleedBox 出血、有效 DPI、标准开本；
以下为评判当时缺口，保留作对比）
- **字体嵌入只计数不检查**：`pdf["fonts"] += len(fonts)`（:178-179），没有遍历
  `/FontDescriptor` 的 `/FontFile*` 判定是否真嵌入，也不区分 Type1/TrueType/CID/Type3。
- **图像有效 DPI 明确不做**（:106 注释），未解析内容流 CTM。
- **出血**：不读 `TrimBox/BleedBox`，无出血量检查。
- **图像链接/XRef 完整性**：不检查 XObject 是否损坏、外部引用。
- **页面尺寸 vs 装订/开本**：只做跨页一致性，不判 A4/16 开等标准开本。
- 加密 PDF 直接短路（:129-140），不尝试空密码解密。

**GB/T 39713 第 3 部分：未真正达成。进度 ~50% → ~65%（V0.9 P0 后）。**

### 4.2 色彩管理 —— 印刷侧强、显示器侧缺

**已做**
- 工艺特性化：工艺库绑定 ICC（`app/services/processes.py`）。
- LAB→CMYK 反查经 lcms2 CMM（`app/services/recipe.py`），ΔE00 统一度量。
- 双基准校准：工艺 ICC 预期 + ISO 12647-2 固体参考（`app/services/calibration.py:77-113`）。
- 工艺级补偿模型（`app/services/compensation.py`），verified 门禁。
- 色域可视化/对比（`app/services/visualization.py`、`app/services/processes.py`）。
- 真 ICC 软打样变换：源 ICC/sRGB → 工艺 ICC → 反变换回 sRGB（`files.py:290-311`）。

**缺失**（V0.9 P0-4 已补：显示器档案、目标亮度/白点/对比度、校准确认有效期、
软打样门禁；以下保留为评判当时缺口）
- **无显示器物理校准链路**（评判时）：代码中无亮度（cd/m²）、白点色温、对比度、
  屏幕色域覆盖率相关实现。仅 V0.1 残留 `/api/correction`（RGB 最小二乘矩阵）与
  `/api/closed-loop`（`app/services/store.py:129-173`）——那是通用 RGB 校正演示，
  未接入工艺工作流，**不构成显示器校准**。V0.9 已补测量数据接收：导入真实
  CGATS/TSV 的 XYZ 白/黑色块，推导白点 xy 与对比度，绝对亮度需外部给定；
  但仍不驱动校准硬件、不生成显示器 ICC。
- 无「屏幕—打样—印刷」统一 ΔE 链（屏幕侧没有测量基准）。
- 扫描仪/打样机特性化缺失（只有印刷机 ICC，靠上传）。
- RGB 工作流（GB/T 43835）未涉及。

**进度：印刷链路 ~75%；显示器链路——档案/有效期/软打样门禁/测量数据接收已落地
（V0.9 P0-4），物理校准与 ICC 生成仍依赖外部硬件与工具；整体 ~50%。**

### 4.3 图像与版面处理 —— 基本未做

**已做**：ICC 色彩空间转换（`files.py:261-319`）、专色**检测**。

**缺失**：分色、层次/曲线调整、专色替换与潘通处理、锐化/去噪、**拼版**。
`拼版` 一词仅出现在 `files.py:241` 的告警文案里（「请确认拼版方式」），无拼版能力。

**进度 ~15%。**

### 4.4 输出 PDF 与标准化 —— 弱

**已做**：`/api/files/convert` 经 ICC 输出 TIFF(CMYK)/PNG(RGB)；PDF 预检读输出意图；
**V0.9 P0-2 已补 PDF/X-4 结构封装**——写入 OutputIntent（工艺 ICC）、XMP
`GTS_PDFXVersion`、TrimBox/BleedBox，硬门禁拦截未嵌入字体与未标定 RGB 图像。

**缺失**（V0.9 P0-2 后剩余）
- 无 **RIP 端全量 PDF/X 校验**（字体子集完整性、色彩空间封闭性、透明度拼合）；
  当前明确标注为「结构级合规」，交付前需 Acrobat Preflight / callas 复核。
- 不改写页面内容与色彩空间：RGB 图像需先用「印前转换」逐图处理，不能在 PDF 级转换。
- PDF 输入仍不支持 ICC 栅格化转换（`files.py`）。
- 无 ISO 15930 符合性自检报告（仅结构写入与硬门禁）。

**GB/T 39713 第 4 部分：结构要素达成，认证级符合性未达成。进度 ~20% → ~45%。**

### 4.5 打样 —— 软打样有其形，硬打样受环境绑定

**软打样（软件项）**：`convert_image` 是真实 ICC 变换，往返逻辑正确（先转工艺空间，
再反变换回 sRGB 出预览）。V0.9 P0-4 起增加显示器校准门禁：未登记 / 未校准确认 /
校准过期时，转换响应 `softproof` 与前端明确标注「预览仅参考」；校准有效且显示器 ICC
由外部工具生成登记后，才满足 GB/T 41466-2022 的可信软打样前提。校准测量可导入
真实 CGATS/TSV（XYZ 白/黑块 → 白点 xy、对比度；绝对亮度由外部给定）并原样留档，
但物理校准、亮度实测与 ICC 生成仍需校准硬件，不在软件职责内。

**硬打样（环境绑定，不计软件缺陷）**：实物样张需打样机。软件应做且已部分就位的是
`app/services/testform.py` 的测量靶标：实色、12 级梯尺（含 75%）、灰平衡格、GATF 星标、
细线、套准标记——可喂给外部打样机与分光光度计。真正缺的软件能力是：
样张的**签样载体格式**（见 4.6）与**网点角度/频率、套准误差的自动测量**（当前仅画标记）。

**进度：软打样 ~55%（ICC 变换真实 + 校准档案/有效期门禁 + 测量数据接收；
显示器物理校准仍需硬件）；硬打样作为数据支撑已就位。整体 ~55%。**

### 4.6 客户确认与签样 —— 缺失（软件项）

无签样/审批状态机，无进制版前的签样门禁。`app/services/evaluations.py` 是 GB/T 34053
主观评分检查单，**非法律意义上的签样基准**。

软件可补（纯代码）：签样记录工作流——样张关联、版本快照、客户确认状态、审批留痕、
确认后才放行下游导出。与有无制版环境无关。

> V0.9 P0 已补：draft/pending/approved/rejected/locked 状态机、证据关联、ICC 变更失效、
> 放行门禁与交接清单。仍缺：法律意义上的签样载体（PDF 签样页 / 电子签名 / 客户签章）。

**进度 0% → ~60%（V0.9 P0 后）。**

### 4.7 制版（CTP）—— 环境绑定项

**制版执行本身**（曝光/显影/网点还原/印版输出）依赖 CTP 硬件，软件无法实现，不计缺陷。

**软件应做且已部分就位**：
- 测控条/校准样张（`testform.py`，含星标/套准/梯级/灰平衡）；
- 校准曲线与墨量建议（`calibration.py:245-330`）；
- 特性数据 CGATS 导出（`calibration.py:332-399`，可喂 ArgyllCMS/i1Profiler）；
- 配方墨量数据（`recipe.py`）。

**真正缺的软件能力**：把上述零散产出**打包成可交接给制版/印刷环节的标准化交付物**
（清单 + 版本 + 校验和 + 签样状态），并对标 GB/T 39713 第 7 部分的数据规范。

**软件侧准备数据 ~30–40%；制版执行不适用。**

### 4.8 贯穿：标准化与认证 —— 精神达成、认证流程缺失

**已做**：ΔE/CIEDE2000 统一度量、测量方法学门禁（`measurement_qa.py` 五规则）、
ISO 12647-2 / ISO 12647-7 / GB/T 17934.2 / GATF 常量口径（`diagnosis.py`）、
测控条生成、校准收敛追踪（`calibration_history.py`）、补偿模型 verified 门禁。
数据可追溯性是本项目最扎实的部分。

**缺失**
- 无 G7 / PSO / FOGRA / GMI 认证工作流（`G7` 仅在 `diagnosis.py` 作为依据文案出现）。
- TVI/灰平衡/密度曲线是计算值，未固化为认证目标曲线资产。
- GB/T 39713 系列仅在告警文案中提及，未落地为可执行检查项。

**进度 ~60%。**

## 5. 本次核校修正

原评判主体成立，以下 3 处表述精确化：

1. **「显示器校准全无」** → 更准确的说法是「**无显示器物理校准链路**」。V0.1 存在
   `/api/correction`（RGB 最小二乘矩阵）与 `/api/closed-loop`（`store.py:129-173`），
   但它是未接入工艺工作流的通用 RGB 校正演示，不含亮度/白点/对比度/显示器 ICC，
   不构成显示器校准，故「显示器链路 0%」的结论不变。
2. **第 1 步「字体嵌入只计数」** → 确认成立，锚点为 `files.py:178-179`，
   可直接补 `/FontDescriptor → /FontFile*` 判定。
3. **第 7 步「软件侧 ~30%」** → 建议记为 **30–40%**：已存在配方、校正曲线、CGATS、
   测控条四类产出，缺的是打包与规范对齐，不是从零开始。

## 6. 软件可补缺口 · 优先级建议

> 排序原则：先补「能形成标准化闭环」的环节，再做「锦上添花」的图像处理。
> 每项给出最小可验证切片，便于按版本切分。

### 不建议做

- CTP 驱动/RIP 集成、实物打样机控制、真机印刷闭环——硬件环节，软件只负责交付标准化数据。
- 自带 Pantone 全量色库——版权风险，走用户导入。
- 宣称「PDF/X 认证」而不做 RIP 端验证——口径必须诚实。

## 7. 一句话结论

项目已把「色彩可控、数据可追溯」做到接近一个专业的**印前色彩数据与标准化平台**，
数据闭环扎实且口径诚实，并为下游制版/打样/签样产出了标准化数据——这正是无制版环境下
软件能承担的职责。真正值得补的软件缺口集中在**预检深水区、PDF/X 结构输出、显示器链路、
拼版与签样工作流、交付打包**；CTP 制版与实物硬打样属硬件环节，不应作为软件进度扣分项。
