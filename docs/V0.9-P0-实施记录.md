## 1. P0-1 PDF 预检深水区

### 1.1 字体真嵌入

- 遍历页面 `/Resources/Font`（资源缺失时沿 `/Parent` 继承链查找）；
- 判定规则：
  - Type0 → `/DescendantFonts` → CIDFont → `/FontDescriptor` → `/FontFile` / `/FontFile2` / `/FontFile3`；
  - 简单字体 → `/FontDescriptor` → `/FontFile*`；
  - Type3 → `/CharProcs`（字形本身内嵌，但提示高精度输出前转曲）；
- 报告结构 `pdf.font_embedding = {total, embedded, not_embedded[], type3[]}`；
- 未嵌入 → **warn**，列出字体名（最多 3 个）；Type3 → info。

### 1.2 出血与成品尺寸

- 读取 `MediaBox / CropBox / TrimBox / BleedBox`；
- 成品线：`TrimBox`（缺失时用 `CropBox` 近似，并 warn「未设置 TrimBox」）；
- 可出血边界：`BleedBox`（缺失时用 `MediaBox`，并记录 `bleed_source`）；
- 四边出血量 = 成品线到出血边界的距离（左/下/右/上）；
- 任一页最小出血 < **3mm** → warn；
- 报告结构 `pdf.page_boxes[]` + `pdf.bleed = {checked, ok, min_mm, page, source}`。

### 1.3 标准开本

- 按成品尺寸匹配 A3/A4/A5/A6、B4/B5、16开/大16开/32开/大32开（容差 ±2mm，横竖版均可）；
- 不匹配 → **info**（包装盒等异形开本不应误报为错误）；
- 报告结构 `pdf.page_format = {name, match, orientation, size_mm}`。

### 1.4 图像有效 DPI

- 解析页面内容流操作符，维护 `q/Q` 图形状态栈与 `cm` CTM；
- 图像 XObject 绘制尺寸取 CTM 的 x/y 轴向量长度：`DPI = px × 72 / pt`；
- Form XObject 递归解析（含 `/Matrix` 与独立 `/Resources`，深度上限 4）；
- 同一图像多次绘制取最低 DPI（最差情况）；
- 低于 300 DPI → warn，报告图像像素与页码；
- 报告结构 `pdf.effective_dpi = {checked, min, low_count, items[]}`，并回填
  `pdf.images[].effective_dpi`。

### 1.5 测试

`tests/test_api_files.py` 新增 7 项：未嵌入字体告警 / 已嵌入字体通过 / 3mm 出血达标 +
A4 开本 / 0 出血告警 / TrimBox 缺失告警 / 36 DPI 告警 / 360 DPI 通过。
测试 PDF 由 pypdf 运行时构造，不引入新依赖。

## 2. P0-2 PDF/X-4 结构封装

### 2.1 写入内容

- `/OutputIntents`：目标工艺 ICC（`/S /GTS_PDFX`、`/DestOutputProfile`、`/N` 通道数、
  `/OutputConditionIdentifier`、`/RegistryName`）；
- XMP 元数据：`pdfx:GTS_PDFXVersion` / `GTS_PDFXConformance = PDF/X-4`、文档标题与 Producer；
- 页面盒：缺失 TrimBox 时按 CropBox/MediaBox 补成品线，缺失 BleedBox 时按 MediaBox 补；
- 原有输出意图被目标工艺 ICC 替换（记录为 info）。

### 2.2 硬门禁与诚实边界

- **硬门禁**（严格模式拒绝）：字体未嵌入、未标定 DeviceRGB 图像、加密 / 损坏 PDF；
- **非严格模式**：仍生成文件，但 `status=warn`、`compliant=false`，逐条列出未达标项；
- **不做**：不重写页面内容与色彩空间、不做透明度拼合、不声称 RIP 端全量 PDF/X 合规。
  响应 `notes` 明确要求交付前用 Acrobat Preflight / callas pdfToolbox 复核。

### 2.3 端点

`POST /api/files/pdfx?process_id=&filename=&strict=&allow_rgb=`

- 请求体：PDF 原始字节（≤40MB）；
- 返回：base64 成品、输出文件名（`-PDFX4.pdf`）、`mode/status/compliant`、
  逐项 `checks`、`output_intent`、页数与 `notes`。

### 2.4 UI

印前转换页的 PDF 流程改为 3 步：上传预检 → PDF/X 封装（输出意图下拉 + 严格模式 +
检查项）→ 完成（下载成品 / 重新封装）。结构级合规提示常显。

### 2.5 测试

`tests/test_pdfx.py` 新增 6 项：结构写入与回读（OutputIntent `/N=4`、ICC 字节一致、
XMP 含 PDF/X-4、TrimBox/BleedBox）、严格模式拒绝未嵌入字体、非严格降级、
严格模式拒绝 RGB 图像、缺 TrimBox 补全告警、非 PDF / 未知工艺 / 空 body 错误码。
E2E 新增 3 项：宽松封装、OutputIntent+XMP 回读、严格模式拒绝 RGB。
浏览器验收：上传 → 封装 → 下载 → pypdf 回读 `/GTS_PDFX` + `/N=4` + XMP，控制台 0 错误。

## 3. P0-4 显示器档案与软打样门禁

### 3.1 档案与校准确认

- 显示器实体：名称 / 型号 / 序列号、目标白点（D50/D55/D65）、目标亮度
  （40–400，推荐 100–120 cd/m²）、目标对比度（≥100:1）、色域覆盖（可选）；
- 校准确认记录：校准日期、有效期（1–60 月）、校准器、软件、实测亮度 / 黑亮度 /
  对比度、白点、色域覆盖、显示器 ICC 名称与指纹、备注；
- 每次确认追加 `history`，保留完整留痕；创建时的首次校准也写入 history。

### 3.2 状态与门禁

- 状态：`ok` / `expiring`（到期前 30 天）/ `expired` / `uncalibrated`；
- `/api/displays/active-status` 与转换响应 `softproof` 字段共用同一判定；
- 未登记、未校准、过期 → `calibrated=false`，前端标注「预览仅参考」；
- 激活显示器互斥（同一时刻只有一个当前显示器）。

### 3.3 端点

| 端点 | 说明 |
|---|---|
| `GET/POST /api/displays` | 列表（含状态）/ 创建（可带首次校准） |
| `GET /api/displays/active-status` | 当前显示器门禁状态 |
| `GET/PATCH/DELETE /api/displays/{id}` | 详情 / 更新目标值 / 删除 |
| `POST /api/displays/{id}/activate` | 设为当前（互斥） |
| `POST /api/displays/{id}/calibrations` | 追加校准确认 |
| `GET /api/displays/{id}/status` | 校准状态 |
| `GET /api/displays/{id}/report` | 校准档案报告（JSON 留痕） |
| `POST /api/displays/{id}/measurements` | 导入屏幕测量（raw CGATS.17 / TSV） |
| `GET /api/displays/{id}/measurements/latest` | 原样导出最近测量文件 + 短摘要 |

### 3.4 屏幕测量导入 / 导出

- 接受真实测量文件（CGATS.17 或 Status-T TSV，复用 `cgats.py` 编码容错解析），
  要求至少 2 个含完整 XYZ 的色块（白 + 黑）；
- **发光屏不接受光谱反射率积分**：必须由测量文件直接给出 XYZ；按 `XYZ_Y` 排序取
  白/黑色块，推导白点 xy（`X/(X+Y+Z)`）与对比度（`Y_white / Y_black`）；
- 绝对亮度优先取查询参数 `white_luminance_cd_m2`，其次读元数据
  `LUMINANCE_CD_M2` / `LUMINANCE` / `WHITE_LUMINANCE`；缺失则不编造，保持 `null`；
- 原始文件按 `sha256[:16]` 命名留档于 `DATA_DIR/display_measurements/`，删除显示器时一并清理；
- 导入结果写入 `measurement`（色块数、XYZ 色块数、白点 xy、对比度、亮度、文件名、
  摘要、导入时间）；校准记录中为空的实测亮度 / 对比度自动回填（已有实测值不覆盖）；
- `GET .../measurements/latest` 逐字节返回原始文件，附 `Content-Disposition` 与
  `X-Content-SHA256`，供外部校准工具复核。

### 3.5 诚实边界

系统**不生成显示器 ICC、不驱动校准硬件**；ICC 由 DisplayCAL / i1Profiler 等外部工具
生成后登记名称与指纹。门禁只回答「这台显示器当前是否可被信任用于软打样」。
测量导入只消费真实文件中的 XYZ，不做光谱→XYZ 的屏上推导，也不把相对 XYZ
自动换算成绝对亮度。

### 3.6 UI

工具箱新增「显示器」页：档案列表（当前 / 状态 / 到期 / 实测）、新增、校准确认、
报告下载、设为当前、删除；测量摘要行 + 「导入测量」（文件 + 可选白场亮度）与
「导出测量」按钮；印前转换的软打样预览与色彩设定阶段显示门禁提示。

### 3.7 测试

## 4. P0-3 签样状态机与放行门禁

### 4.1 状态机

```
draft ──submit──▶ pending ──approve──▶ approved ──lock──▶ locked（终态）
                     │
                     ├──reject──▶ rejected ──submit──▶ pending
                     └──withdraw──▶ draft
```

硬约束：
- `submit` 前至少关联一项依据（校准会话 / 测量会话 / 主观评价 / 样张文件标识）；
- `reject` 必须填写理由；
- 所有动作必须填写操作人；
- `locked` 为终态，不可再迁移、不可删除；
- 删除仅限 `draft`。

### 4.2 数据模型

`data/signoffs.json`（JsonStore 原子写）：

```
{
  id: "sg_<hex12>", process_id, title, job_no, state,
  created_by, created_at, updated_at,
  evidence: {calibration_session_id, measurement_session_id,
             evaluation_id, testform, file_name},
  snapshot: {process_name, icc_sha256, device_space, paper, ink},
  decision: {action, by, at, note} | null,
  locked_at, release_token,
  history: [{at, action, from, to, by, note}]
}
```

创建时快照工艺的 ICC 指纹；**ICC 替换后旧签样自动失效**（`gate.reason = icc_changed`），
必须重新签样。

### 4.3 门禁与交接清单

- `GET /api/signoffs/gate?process_id=` → `{allowed, reason, message, signoff_id, ...}`；
- `GET /api/signoffs/release-manifest?process_id=` → 未放行返回 **409**；放行时输出
  工艺信息 + 签样快照 + 证据 + 放行令牌，作为 P2 交付包的第一个消费者。
- `lock` 时生成确定性 `release_token = sha256(id + icc + evidence + decision)`，
  下游可据此校验交接版本。

### 4.4 端点

| 端点 | 说明 |
|---|---|
| `POST /api/signoffs` | 创建草稿（证据引用会校验存在性与工艺归属） |
| `GET /api/signoffs` | 列表（按工艺 / 状态过滤） |
| `GET /api/signoffs/gate` | 放行门禁 |
| `GET /api/signoffs/release-manifest` | 交接清单（未放行 409） |
| `GET /api/signoffs/{id}` | 详情（含历史） |
| `POST /api/signoffs/{id}/submit` | 提交确认 |
| `POST /api/signoffs/{id}/approve` | 批准 |
| `POST /api/signoffs/{id}/reject` | 驳回（理由必填） |
| `POST /api/signoffs/{id}/withdraw` | 撤回草稿 |
| `POST /api/signoffs/{id}/lock` | 锁定 + 生成放行令牌 |
| `DELETE /api/signoffs/{id}` | 删除（仅草稿） |
