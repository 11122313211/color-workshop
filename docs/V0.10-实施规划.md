## 1. 背景与目标

V0.9 已形成预测 → 实测 → 补偿 → 校准 → 收敛 → 签样的主链，但证据分散在工艺、补偿、
校准轮次、测量会话、配方记录与签样中：

- 无法用一份版本化交付物回答“当前签样依据了哪一版 ICC/校准/测量/配方证据”；
- “配方”一词混合了设备分色值与实物调墨配方，容易被误读；
- 工艺未记录 M0/M1/M2 条件，证据比较缺少条件元数据；
- 已有光谱数据停留在测量层，未形成多光源同色异谱风险视图；
- 签样只在 ICC 变化时失效，不能识别“护照证据版本已变化”。

V0.10 的目标是补上**证据版本化**与**光谱风险证据**，而不是继续扩张模型能力：

1. 新增工艺护照，统一汇总既有证据并给出动态状态、hash、版本与导出；
2. 显式拆分“分色值（设备值）”与“调墨配方”，前者继续可用，后者本版不实现；
3. 记录 M0/M1/M2 测量条件，缺失时诚实警告；
4. 用现有 CGATS 光谱数据计算多光源工程同色异谱风险；
5. 签样可引用护照 hash，证据版本变化时门禁返回 `passport_changed`。

## 2. 范围、假设与不做

### 2.1 本版范围

- 语义与兼容字段：`measurement_condition`、`passport_summary`、`recipe_kind/recipe_meta`、
  `passport_id/passport_hash`。
- `PassportStore`、`data/passports.json` 与幂等迁移。
- 工艺护照服务、5 个护照端点、JSON/Markdown 导出。
- 光谱服务、3 个光谱端点、四光源同色异谱风险。
- 配方单导出与 CSV 尾部 `recipe_kind` 列。
- 工艺详情护照卡/详情模态、监控页光谱卡/曲线模态、签样护照关联与门禁提示。
- 亮/暗、375px、无障碍与回归验收。

### 2.2 假设

- 现有数据保留：2 个工艺、9 条配方、0 个测量会话；迁移不删除旧数据。
- 验收使用合成光谱 fixture 与现有 e2e 光谱文本，不依赖外部硬件。
- 存储仍为 JSON；不引入数据库。
- 默认条件为 `D50/2°`、`D65/2°`、`A/2°`、`FL11/2°`；`FL11` 来自
  `colour-science` 的 CIE F11。
- 护照每工艺最多 50 版。
- 护照导出只做 JSON/Markdown；PDF 由浏览器打印生成。

### 2.3 本版不做

- 不训练模型、不微调模型、不新增模型推理依赖；AI 只保留接口与历史能力位。
- 不实现基础油墨 KM 调墨；`ink_formula` 仅保留类型占位。
- 不做跨项目合并，不做破坏性 API 重命名；破坏性变更留到 V1.x。
- 不把工程同色异谱指标包装成 CIE 15 特殊同色异谱指数 MI。
- 不做 UI 可配置风险阈值，不在本版生成 PDF 护照。

## 3. 兼容策略

### 3.1 总原则

- 新增字段全部可选；旧 API 响应字段不删不改。
- 新增路由全部为加法式；旧客户端不调用新路由时行为不变。
- 旧数据缺新字段时按默认语义读取，不强制回填、不改写原文件。
- 所有新写盘经 `JsonStore` 原子写与损坏隔离备份语义。

### 3.2 默认值

| 对象 | 新字段 | 旧数据默认 |
|---|---|---|
| `ProcessOut` | `measurement_condition` | `""`（未登记） |
| `ProcessOut` | `passport_summary` | `null` |
| `RecipeResult` | `recipe_kind` | `device_values` |
| `RecipeResult` | `recipe_meta` | 单位/基准/说明的默认对象 |
| `Signoff` | `passport_id` / `passport_hash` | `""`（legacy，仍按 ICC 指纹） |

### 3.3 迁移

- 幂等迁移脚本补默认字段并初始化 `data/passports.json`。
- 重复运行不得新增重复记录、不得改变旧记录可读性。
- `processes.json`、`recipes.json`、`signoffs.json` 的旧 fixture 迁移后，旧 API 响应
  仍可解析。
- 迁移失败可重跑；不得为“修正”而删除用户已有记录。

## 4. 数据契约

### 4.1 工艺

`ProcessOut` 增加：

- `measurement_condition: str = ""`：空串 / `M0` / `M1` / `M2`；
- `passport_summary: dict | null = None`：最近护照的轻量摘要，由路由按需注入；
  护照损坏或旧数据时置空，不影响工艺主数据读取。

创建与编辑工艺均可选择条件；非法值返回 422，不得静默降级为 M0/M1/M2 之一。

### 4.2 配方

`RecipeResult` 保持原字段：

- `recipe: dict[str, float]` 不变，旧列顺序不变；
- 新增 `recipe_kind: str = "device_values"`；
- 新增 `recipe_meta`：至少包含 `unit=percent`、`basis=device_channels`、说明
  “分色值（设备值），不是基础油墨调墨配方”；
- 旧配方记录读取时缺 `recipe_kind` 则补 `device_values`。

### 4.3 签样

签样创建请求、证据、快照可增加：

- `passport_id: str = ""`
- `passport_hash: str = ""`

两者均为可选；只传其中一个时按实现约定补全/校验。旧签样没有这两个字段时，
门禁继续走 V0.9 的 ICC 指纹逻辑，不强制迁移。

### 4.4 护照模型

| 模型 | 用途 | 关键字段 |
|---|---|---|
| `PassportWarning` | 结构化警告 | `code`、`level`、`message` |
| `PassportSummary` | 工艺响应/列表的轻量摘要 | 护照 id、版本、hash、生成时间、动态状态、警告数、最高光谱风险 |
| `PassportOut` | 护照详情 | 工艺 id、版本、hash、生成时间、`created`、工艺快照、证据、警告、动态状态与原因 |
| `PassportExport` | 导出结果 | 护照 id、版本、格式、文件名、内容 |

`PassportStore` 逻辑上按“工艺 → 版本列表”组织，至少保存不可变证据快照、hash 与生成时间；
读取时再注入当前工艺状态。存储文件为 `data/passports.json`。

### 4.5 光谱模型

| 模型 | 用途 | 关键字段 |
|---|---|---|
| `SpectralMetamerismRequest` | 两组直接光谱比较 | `spectral_a/b`、可选 label、默认四条件（均 2°） |
| `SpectralConditionOut` | 单光源结果 | condition、显示 label、illuminant、observer、两组 Lab、ΔE00、risk |
| `SpectralMetamerismResponse` | 汇总 | 各条件、最大 ΔE、最差光源、总体 risk、warnings、disclaimer |
| `SpectralCompareRequest` | 双会话比较 | session_a/b、`top_n` |
| `SpectralCompareResponse` | 双会话结果 | 两会话摘要、matched、top 差异、最大 ΔE、最差光源、risk、warnings、disclaimer |

## 5. 工艺护照

### 5.1 证据汇总

护照服务 `app/services/passport.py` 汇总：

| 证据 | 内容 | 缺失处理 |
|---|---|---|
| ICC | 当前 ICC sha256、通道数、可读性 | 缺失/不可读 → `invalid` |
| 补偿 | 是否有模型、模型指纹/更新时间 | 与快照不一致 → `stale` |
| 校准轮次 | 轮次数、最近轮次、收敛信息；只认当前 ICC 一致轮次 | CMYK 无轮次 → `incomplete` |
| 测量会话 | 会话数、verified 数、条件、时间 | 无 verified → `incomplete` |
| 配方统计 | 记录数、达标率、最近记录摘要 | 如实为空，不虚构 |
| 光谱覆盖 | patch 数、波长范围、可比较会话数、最高风险 | 无光谱 → `available=false` + warning |
| 条件 | M0/M1/M2 登记值 | 未登记 → warning，不做条件比较 |

护照不包含签样状态，不读取“是否已签样”作为证据，避免循环依赖。

### 5.2 状态判定

按以下优先级动态判定，状态不写死到历史快照：

| 优先级 | 状态 | 条件 | 含义 |
|---|---|---|---|
| 1 | `invalid` | ICC 缺失或不可读 | 证据不可用 |
| 2 | `stale` | ICC/补偿/校准指纹与快照不一致 | 证据已变化，需刷新/重签 |
| 3 | `incomplete` | 无 verified 测量，或 CMYK 工艺无校准轮次 | 证据链不完整 |
| 4 | `valid` | 不满足以上条件 | 当前证据链完整 |

“未生成护照”是 UI/API 的不存在状态，不是第五种护照状态；不得用 `valid` 冒充。
每类转换应带 `status_reasons`（`PassportWarning[]`），前端可直接展示原因。

### 5.3 哈希

- 对规范化 JSON 做 sha256。
- 规范化要求：稳定键序、固定数值格式；数值按字段固定 4 位小数，消除浮点尾差。
- hash 排除 `generated_at`、`version`、`passport_hash`、`status`、`status_reasons`、
  `id`；派生状态/展示 id 固定为非证据字段，避免同一证据因展示状态变化而漂移。
- 相同证据内容重复 `POST`，hash 不变并返回现有版本，不新增版本。
- 护照 hash 只证明“证据快照内容一致”，不证明 ICC 认证、客户批准或物理颜色合格。

### 5.4 版本

- 版本为工艺内单调递增的整数，展示为 `vN`；
- 内容变化才追加版本；
- 历史版本不可变，不允许编辑或覆盖；
- 每工艺最多 50 版；已在 Sprint 2 固化并测试裁剪策略：达到上限裁剪最旧版本，
  不静默覆盖最新版本；测试 55 次生成保留 `v6–v55`；
  若裁剪导致旧签样引用失效，门禁返回 `passport_changed`；
- `passport_summary` 只引用最近版本，历史通过版本端点读取。

### 5.5 签样门禁与交接

- 护照不嵌入签样；签样通过可选 `passport_hash` 引用护照。
- 签样含 `passport_hash` 时，`SignoffStore.gate()` 以当前最新护照 hash 校验；
  不一致返回 `reason=passport_changed`，并输出签样 hash/当前 hash 摘要。
- 只有状态为 `valid` 的护照可被新签样关联；门禁还会动态检查最新护照状态，
  `incomplete/stale/invalid` 分别返回 `passport_incomplete/passport_stale/passport_invalid`，
  避免“hash 未变但证据已失效”仍放行。
- legacy 签样没有护照字段时，不触发护照门禁，仍按 ICC 指纹判定。
- `release_manifest` 增加护照摘要（id/version/hash 前缀/status/warnings/光谱风险），
  让交接清单可追溯证据版本。

## 6. 光谱 / 同色异谱

### 6.1 积分与条件

- 服务位于 `app/services/spectral.py`；
- 复用 `cgats.integrate_lab` 与 `cgats.white_xyz`；
- 默认四条件：`D50`、`D65`、`A`、`FL11`，均为 2° 观察者；
- UI 将 `FL11` 显示为 **CIE F11**；
- 输入波长限定在 CGATS 积分网格 `380–730nm`；`conditions=[]` 返回 422；
- 各波长网格独立积分，不重采样、不插值到统一网格。

### 6.2 输出指标

单对光谱至少输出：

- 每个条件下的两组 Lab；
- 每个条件的 ΔE00；
- 最大 ΔE；
- 最差光源；
- 总体风险等级；
- 警告与免责声明。

双会话比较：

- 按 patch label 匹配；
- 输出匹配数、top 差异（label/ΔE00/风险/各光源摘要）；
- 无匹配或无可比光谱时 `available=false`/`none`，不伪造结果。

### 6.3 风险阈值

| 最大 ΔE00 | 等级 | 标签 |
|---|---|---|
| `≤ 1.0` | `low` | 低风险 |
| `≤ 2.0` | `medium` | 中风险 |
| `> 2.0` | `high` | 高风险 |

常量集中定义，本版不做 UI 配置。边界归属必须通过测试固定。

### 6.4 边界与免责

- 荧光增白纸（OBA）反射率 >1 合法；不得截断到 1.0；
- 反射率 <0 或 >1.5 给 warning；
- 波长范围不足、网格过稀、坏数据：能算则算并警告，不能算则不可用；
- 无光谱时护照光谱段 `available=false` 并给 warning；
- 常显：“**工程同色异谱风险指标，不等同 CIE 15 特殊同色异谱指数 MI**”；
- 该指标不替代标准光源箱目视评价、客户签样或物理打样。

## 7. API 清单

### 7.1 新增端点

| 端点 | 方法 | 请求/参数 | 响应/说明 | 主要错误 |
|---|---|---|---|---|
| `/api/processes/{pid}/passport` | POST | 无 body | 生成/刷新；响应 `created` 表示是否新增版本 | 404 工艺不存在 |
| `/api/processes/{pid}/passport` | GET | — | 当前最新护照（动态状态） | 404 工艺/护照不存在 |
| `/api/processes/{pid}/passport/versions` | GET | — | 版本摘要列表 | 404 工艺不存在 |
| `/api/processes/{pid}/passport/{version}` | GET | path version | 指定版本详情 | 404 版本不存在 |
| `/api/processes/{pid}/passport/{version}/export` | GET | `format=json\|md` | 文件下载（JSON/Markdown） | 404 / 422 format |
| `/api/spectral/metamerism` | POST | `spectral_a/b`、label、conditions | 四光源 Lab/ΔE00、最大风险、最差光源 | 422 光谱非法 |
| `/api/spectral/compare` | POST | `session_a/b`、`top_n` | 双会话差异 top、风险、警告 | 404 会话 / 422 比对失败 |
| `/api/spectral/sessions/{sid}/summary` | GET | path sid | 会话光谱摘要 | 404 会话不存在 |
| `/api/recipes/{rid}/export` | GET | `format=json\|md` | 配方单导出（设备值语义） | 404 配方 / 422 format |

### 7.2 既有端点修改

| 端点 | 修改 |
|---|---|
| `POST /api/processes` | 增加可选 `measurement_condition`；响应含 `passport_summary=null` |
| `PATCH /api/processes/{id}` | 可编辑 `measurement_condition`；响应含当前护照摘要 |
| `POST /api/signoffs` | 可选 `passport_id/passport_hash`；关联不存在/不匹配 422 |
| `GET /api/signoffs/gate` | hash 变化 → `passport_changed`；非 valid → `passport_incomplete/stale/invalid`；legacy 路径不变 |
| `GET /api/signoffs/release-manifest` | 增加护照摘要 |

### 7.3 错误码与负向场景

- 404：工艺不存在、护照未生成、护照版本不存在、测量会话不存在、配方不存在。
- 422：非法测量条件、非法导出 format、非法光谱、无可比 patch、护照 id/hash 不匹配。
- 409：沿用 V0.9 release-manifest 未放行语义。
- 无光谱、坏光谱、ICC 替换、旧签样/旧配方：均需有显式测试。

## 8. UI 实现

### 8.1 工艺护照

- 工艺详情页新增护照卡：状态、版本、hash 前缀、证据覆盖、警告、最近生成时间。

### 8.2 光谱 / 同色异谱

- 监控页新增光谱卡：双会话选择、按 label 匹配、top 差异、最大 ΔE/最差光源/风险。

### 8.3 配方与签样

- 配方结果卡标题改“分色值（设备值）”；副文案说明不是实物调墨配方。
- 新增“导出配方单” JSON/Markdown。
- CSV 旧列序不变，末尾加 `recipe_kind`。
- 签样创建模态可选关联护照，显示状态/版本/hash 前缀；仅 `valid` 可关联。
- `passport_changed` / `passport_stale` / `passport_invalid` / `passport_incomplete`
  门禁展示 hash/状态变化，approved/locked 签样提供“重新签样”，不提供忽略放行。

### 8.4 响应式与无障碍

已实现与已验收：

- 375px 截图覆盖护照卡与光谱卡；亮/暗主题截图覆盖光谱页；

## 12. 风险与决策点

| 风险 | 影响 | 应对 |
|---|---|---|
| hash 规范化不稳定 | 相同内容生成多版本、签样误失效 | 固定键序/数值格式；排除生成时间/版本/hash/派生状态；用固定 fixture 测稳定 |
| 状态优先级歧义 | invalid/stale/incomplete 混用 | 固定 invalid → stale → incomplete → valid，并测组合条件 |
| 50 版裁剪策略不明 | 历史/签样引用丢失 | Sprint 2 固化策略、测试；最新版不得静默覆盖；旧签样引用被裁剪时 gate 返回 `passport_changed` |
| 护照/签样循环依赖 | 模型与门禁耦合、难迁移 | 护照不读签样状态；签样只引用 hash；release_manifest 单向汇总 |
| FL11 命名混淆 | 与 D50 等光源误标 | 数据层用 `FL11`，UI 统一显示 CIE F11；常量集中 |
| OBA/网格差异 | 截断高反射率、错误重采样 | 允许 >1，超出 <0/>1.5 仅警告；各网格独立积分 |
| 合成 fixture 过期 | 只通过合成数据、真实数据失败 | 同时用现有 e2e 光谱文本；保留真实数据导入回归 |
| 375px 信息密度 | 状态/hash/表格挤爆 | 已完成 375px 截图验收；表格纵向卡片化列为后续优化 |
| 版本与性能 | 50 版列表/导出变慢 | 版本摘要轻量化；历史和详情分端点；设置响应体量检查 |
| 语义越界 | 把设备值称调墨配方、把风险称 MI | 固定文案与免责声明；7 步/设计/PRD 同口径 |
