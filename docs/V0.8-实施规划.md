# V0.8 实施规划 —— 校准收敛与复测验证

> 版本目标：补全 V0.7 校准闭环的最后一环——**收敛追踪**。V0.7 回答「差距多大、怎么改」，V0.8 回答「改了之后到底改善没有、几轮能收敛」。把单轮校准升级为可运营的收敛流程：应用建议 → 落库轮次 → 重新打印测量 → 报告自动对比上一轮 → 收敛判定。

## 1. 背景

V0.7 交付的校准向导在步骤 3 提示「应用建议 → 重新打印校准版并测量 → 报告应转向达标」，但系统不记录轮次：无法回答「这是第几轮」「比上轮改善多少」「是否收敛」。本版本把校准从一次性动作升级为带记忆的迭代流程。

与既有能力的关系：

| 环节 | V0.7 现状 | V0.8 |
|---|---|---|
| 校准报告 | 实时计算不落库 | apply 时落库为**轮次**（含报告摘要 + 应用偏置） |
| 复测验证 | 人工看报告 | 新报告自动与上一轮对比 → 改善/持平/恶化 |
| 收敛判定 | 无 | 按工艺聚合轮次趋势 → converged / improving / worsening / flat |
| 历史 | 无 | 工艺详情页校准历史卡（轮次列表 + max ΔE sparkline + 收敛 chip） |

## 3. 数据模型

`data/calibrations.json`（key=round_id，JsonStore，仿 EvaluationStore）：

```
{
  id: "cal_<hex12>",
  process_id, icc_sha256, session_id,
  created_at,                      # apply 时刻
  overall: "ok|suggest|needed",
  summary: {max_de_expected, avg_de_expected, solid_iso_fail, wedge_max_ok, wedge_avg_ok},
  ink_suggestions: [{channel, delta_pct, ...}],   # 报告快照
  bias_before: [4], bias_after: [4],              # 应用前后偏置
  exports_digest: {max_de_expected, avg_de_expected}  # 冗余便捷字段
}
```

**幂等**：同一 session 重复 apply → 更新该轮（不新增）。
**ICC 失效**：轮次保留历史，但收敛统计只计入 `icc_sha256` 与当前工艺一致的轮次。

## 4. 判定算法

### 4.1 轮次对比 compare_rounds(current_report, prev_round)

- 等级序：needed=0 < suggest=1 < ok=2；
- verdict：等级升或 max_de_expected 下降 >0.05 → **improved**；等级降或上升 >0.05 → **worsened**；否则 **flat**（0.05 为报告噪声地板，与 8-bit Lab 量化 ±0.4 同量级）；
- 输出：{prev_round_id, created_at, prev_overall, prev_max, prev_avg, verdict, d_max, d_avg, per_channel: [{channel, prev_delta, cur_delta, d}]}。

### 4.2 收敛判定 convergence_for_process(rounds)

- 轮次 <2（按当前 icc_sha256 过滤后）→ n/a；
- 任一轮 overall == ok → **converged**（并给收敛轮次号）；
- 否则按最近两轮 max_de_expected 趋势：下降 → improving，上升 → worsening，±0.05 内 → flat。

## 5. 端点与 UI

- `POST /api/qc/calibration/apply`：响应增加 `round_id`、`round_no`（当前工艺轮次数）、`verdict`（本轮报告 vs 上一轮）；
- `GET /api/qc/calibration?session_id=`：响应增加 `prev_round_compare`（存在历史轮次时）；
- `GET /api/qc/calibration/history?process_id=`：{rounds（倒序）, convergence, round_no}；
- `DELETE /api/processes/{id}`：级联清理轮次（routers/processes.py 补一行）。

UI：
- 向导步骤 2 报告顶部：轮次对比卡（「较上轮：max ΔE 4.76 → 2.10 · 改善」徽标）；
- 步骤 3 应用后：「已记录为第 N 轮校准」；
- 工艺详情页：补偿模型卡旁新增**校准历史卡**（轮次列表 + 收敛 chip + max ΔE sparkline）；
- 监控页校准状态行：加「第 N 轮」。
