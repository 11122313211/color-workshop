## 1. 交付结论

V0.11 在 V0.10 工艺护照与证据链之上完成：

1. **归档优先**：`DELETE` 不再硬删；默认列表排除归档，归档可恢复、只读；
2. **写门禁**：所有会改变归档工艺证据的 API 统一返回 409 `PROCESS_ARCHIVED`；
3. **依赖与永久清理**：依赖计数、confirm 门禁、派生记录删除、测量/评价解绑、
   签样孤儿标记；
4. **完整性审计/修复**：孤儿扫描、Dry Run、幂等 apply、未引用 ICC 隔离；
5. **护照版本历史**：`is_latest`、签样引用列表与计数，归档后历史可读；
6. **可用性**：模态 `aria-labelledby`/`inert`、Tab/Shift+Tab/Esc/焦点还原、
   光谱 Canvas 摘要与非颜色编码、375px 卡片化；
7. **跨平台 E2E**：移除 Windows 系统 ICC 依赖，统一内置测试 profile。

## 3. API 与错误契约

### 3.1 生命周期

| 端点 | 方法 | 结果 |
|---|---|---|
| `/api/processes?include_archived=0\|1` | GET | 默认仅 active；1 包含归档 |
| `/api/processes/{pid}/archive` | POST | body `{reason, actor}`；幂等 |
| `/api/processes/{pid}/restore` | POST | 恢复 active |
| `/api/processes/{pid}` | DELETE | 归档（query 可带 reason/actor） |
| `/api/processes/{pid}/permanent?confirm={pid}` | DELETE | 仅 archived + confirm 匹配 |
| `/api/processes/{pid}/dependencies` | GET | 7 类计数、状态分布、blockers、can_permanent_delete |

归档写操作错误：

```json
{"detail":{"code":"PROCESS_ARCHIVED","message":"工艺已归档，只读"}}
```

覆盖：PATCH、ICC PUT、predict/verify、QC 测量导入/删除、评价创建/打分/删除、
签样创建/迁移/删除、护照 POST、文件 convert/pdfx、补偿重置。读取、gamut、
ICC 下载、护照/versions 详情保持 200。

永久清理 confirm 不匹配返回 422；未归档返回 409 `not_archived`。

### 3.2 完整性

| 端点 | 方法 | 关键字段 |
|---|---|---|
| `/api/integrity/report` | GET | `generated_at`, `summary`, `details`, `actions` |
| `/api/integrity/repair` | POST | `dry_run`, `applied`, `planned`, `counts`, `after` |

默认 `dry_run=true`；`actions=[]` 表示全部。动作筛选兼容 action/category/detail
及别名；未知动作 422。

### 3.3 护照历史

`GET /api/processes/{pid}/passport/versions` 每行：

```json

  "id": "pp_...",
  "version": 2,
  "is_latest": true,
```

引用查找按 process_id 限定，`passport_id` 或 `passport_hash` 任一命中（OR 语义）。

## 4. 数据语义

### 4.1 归档

- 旧数据缺归档字段按 active；`archived_at==""` 为 active。
- 归档不删除 ICC、配方、补偿、校准、护照、测量/评价/签样。
- 归档幂等：重复归档不刷新 `archived_at`；恢复幂等。
- 归档不是删除，具备独立 `archive_reason/archived_by` 审计字段。

### 4.2 永久清理

| 数据 | 语义 |
|---|---|
| 工艺 | 删除元数据 |
| ICC | 删除落盘文件 |
| 配方 / 补偿 / 校准 / 护照 | 删除 |
| 测量会话 | `process_id=""`，写 `detached_from_process`、`detached_at` |
| 主观评价 | 同上，解绑保留 |
| 签样 | 不删除，写 `orphaned_at`、`orphan_reason=process_permanently_deleted` |

响应示例：

```json
{
  "status": "permanently_deleted",
  "deleted": {"processes":1,"icc":1,"recipes":1,"compensation":1,"calibrations":1,"passports":1},
  "detached": {"measurement_sessions":1,"evaluations":1},
  "orphaned": {"signoffs":1}
}
```

注意：签样仍保留原 `process_id` 作为审计来源，同时增加孤儿字段；不要把它重新
视为可绑定到其他工艺。

### 4.3 完整性

- 孤儿派生记录：删除；
- 孤儿测量/评价：解绑保留；
- 孤儿签样：标 orphaned；
- 未引用 ICC：移到 `data/orphaned_icc/`，重名追加 `.1`、`.2`；
- 缺失 ICC：仅报告，不伪造/不自动补；
- Dry Run：不创建目录、不写任何 store 或 ICC；
- apply 后重扫，幂等第二次返回 0 变更。

## 6. 兼容与限制

- `ProcessStore.delete()` 保留为内部硬删除，仅供永久清理/测试清理；外部 API 不再直接暴露。
- 旧数据不强制迁移；字段缺省按 active/未孤儿处理。
- 多进程/多 worker 下 JSON 写锁仍是进程内锁；本版未实现跨进程事务。
- 完整性修复不自动启动执行；真实数据 4 条 issue 未 apply。
- 200% 缩放使用 CSS zoom 代理验证；完整 NVDA/VoiceOver 全页审计未完成。
- 截图脚本为护照历史造 2 个 incomplete 版本；签样引用字段由 E2E/pytest 验证，
  截图本身不宣称显示引用证据。
