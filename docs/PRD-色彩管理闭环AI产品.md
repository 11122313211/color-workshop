> 版本：v1.0 ｜ 日期：2026-11-12 ｜ 状态：草案
> 定位：**软硬件一体的通用色彩管理闭环 AI 平台**

---

## 1. 产品概述

### 1.1 背景与问题

色彩管理的核心目标是让颜色在"采集—转换—显示—输出"全链路中保持一致。行业已有成熟的标准基础——**ICC（International Color Consortium）** 发布的 ICC.1 规范（ISO 15076-1，最新 ICC.1:2022 / profile v4.4.0.0）定义了"设备—PCS（描述文件连接空间）—设备"的标准化转换框架，CMM（色彩管理模块）负责执行实际的跨设备色彩转换。

然而，这套体系本质上是**静态的、单次的转换**，在"闭环"层面存在明显断裂：

- **测量环节**：依赖人工使用色度计/分光光度计布点、拍摄色卡、采集数据，操作繁琐、专业门槛高。
- **校正环节**：从测量出的 ΔE（色差）到生成校正参数（显示器 LUT、印刷墨量补偿、染料配方、设计稿修正），**几乎完全依赖人工经验与手动操作**，是整个闭环中最薄弱的环节。
- **验证环节**：校正后复测、判断是否达标、不达标再手动返工，形成人工循环，周期长、一致性差。
- **归因环节**：测出色差后，判断是设备、材料还是流程问题，依赖人工经验，缺乏自动诊断。

色彩空间转换（ICC CMM）本身已高度自动化，真正"断"在**测量自动化、智能校正、闭环验证迭代、色差归因**这四个高度依赖人工的环节。这正是 AI 可以切入、形成差异化闭环的机会。

### 1.2 产品定位

**软硬件一体的通用色彩管理闭环 AI 平台**。

以 **ΔE / CIEDE2000** 为统一度量，将"**测 — 析 — 校 — 验 — 迭代**"五个环节整合为端到端自动化的闭环：

```
测量采集 → 分析判定 → 智能校正 → 闭环验证 → 迭代修正 →（回到测量，持续闭环）
```

- **硬件做测量**：配套色度计、分光光度计、色卡等测量设备，负责物理色彩数据采集。
- **软件做闭环**：AI 云端/本地引擎负责色卡识别、智能校正、ΔE 预测、闭环迭代与归因，形成自动反馈回路。
- **通用平台**：不局限于单一场景，覆盖显示校准、印刷印前、电商零售、纺织印染、影视影像、内容创作等多场景，通过插件化扩展。

### 1.3 核心价值

| 价值维度 | 说明 |
|---|---|
| **降低门槛** | "拍照即完成标定"，将专业色彩管理操作简化为自动化流程，覆盖非专业用户。 |
| **提升精度** | AI 混合架构（ICC 物理先验 + 神经网络补非线性）在宽色域、HDR、特殊材质等场景下提升校正精度。 |
| **缩短周期** | 闭环自动迭代取代人工反复校样、返工，显著缩短色彩校验周期。 |
| **沉淀资产** | 设备 profile、色卡数据、测量记录、校正历史沉淀为可复用的色彩资产库。 |
| **统一度量** | 以 ΔE/CIEDE2000 为统一验收标准，跨设备、跨场景、跨团队对齐色彩语言。 |

### 1.4 目标用户

| 用户分层 | 典型角色 | 核心诉求 |
|---|---|---|
| 专业创作者 | 设计师、摄影师、影视调色师 | 跨设备色彩一致性、精准校色、高效工作流 |
| 工业用户 | 印刷工程师、纺织印染质检、涂料/塑料配色 | 打样与量产色彩一致、批次色差控制、自动配色 |
| 电商/零售 | 电商运营、品牌方、视觉团队 | 商品图与实物色差控制、降低退货与投诉 |
| 企业管理者 | 色彩管理者、IT/品质负责人 | 多设备统一管理、数据可追溯、权限与合规 |

## 2. 市场与竞品分析

### 2.1 行业技术标准基础

产品算法底座建立在以下行业标准之上，无需自造基础：

- **ICC.1:2022（profile v4.4.0.0）**：色彩管理基石，定义 profile、CMM、PCS（D50 白点的 CIELAB/XYZ）、四类渲染意图（Perceptual / Saturation / Relative Colorimetric / Absolute Colorimetric）。
- **色彩空间**：sRGB（IEC 61966-2-1，消费默认）、Adobe RGB（1998，印刷摄影）、DCI-P3（影院，Apple Display P3 用 D65）、Rec.2020（UHD/HDR）、ProPhoto RGB（极宽色域，内部工作空间）。色域大小关系：sRGB < Adobe RGB < DCI-P3 < Rec.2020 < ProPhoto RGB。
- **色差指标**：CIELAB（感知均匀色彩空间）、ΔE\*ab、**CIEDE2000（ΔE00，工业界最常用验收标准）**、ΔEcmc。
- **色彩外观模型**：CIECAM02（现行标准，宽色域/HDR 有短板）、CAM16、CIECAM16（CIE 248:2022 标准化）。

### 2.2 六类应用场景及痛点

| 场景 | 核心痛点 | 对闭环的需求 |
|---|---|---|
| **印刷/出版** | 打样与印刷不一致、返工周期长、不同机台/纸张差异、同色异谱 | 印前设计→打样→上机检测→自动校正回传，减少反复看样调墨 |
| **显示/屏幕校准** | 出厂色准参差、随时间老化、广色域/OLED 滤片式色度计误差、8-bit LUT 局限 | 定时校准→检测偏差→生成校正→回写 LUT→复测验证 |
| **电商/零售** | 商品图与实物色差致退货、卖家端显示器各异、买家端设备各异 | 拍摄标定→修图校准→上传转换校验→展示适配→色差投诉归因 |
| **服装/纺织/印染** | 染料批次色差、耐漂耐洗变色、依赖标准光源箱目视对色、配色靠经验 | 测色→比对标准样（ΔE00 判定）→配色推荐→打样验证→反馈修正 |
| **摄影/影像/影视** | 拍摄到显示到交付链路长、HDR 标准多样、现场监看与交付不一致 | ACES 统一工作流→IDT→工作空间调色→ODT 映射→监看校准→交付验证 |
| **数字内容创作** | 跨设备设计稿色彩不一致、跨团队协作"各显各色"、多端输出转换靠人工 | 工具内嵌色彩管理→设备自动校准→色彩空间自动标注转换→输出适配→一致性校验 |

### 2.3 竞品分层

| 厂商 | 能力特点 | 闭环程度 | 主要局限 |
|---|---|---|---|
| **X-Rite（含 Pantone）** | 产品线最全，覆盖屏幕—印前—机台—品牌色供应链；i1Display、i1Pro 3、eXact、PantoneLIVE | 印刷领域闭环相对完整（测—比—调），显示端需配合硬件 | 设备昂贵、偏专业印刷影视；同色异谱等物理问题无法纯软件解决 |
| **Datacolor** | 消费级/摄影显示校准强，Spyder 系列，支持 3D LUT 导出 | 显示端"校准—导出 LUT—应用"小闭环 | 广色域/OLED 光谱校正有限，工业印刷标准支持不如 X-Rite |
| **Calibrite** | 接手 X-Rite 摄影/显示校准线，ColorChecker 系列，面向创作者 | 拍摄到显示到打印的中等闭环 | 无印刷机台方案，偏消费/专业创作者 |
| **Adobe** | 应用层色彩管理最成熟，Camera Raw/Photoshop，Adobe ACE CMM | 软件"转换"闭环完整，但**不涉及物理测量与硬件校正** | 无自动测量反馈，依赖用户正确配置 |
| **Windows WCS / macOS ColorSync** | 系统级 ICC 色彩管理，加载 vcgt 校准数据 | 系统层转换管道，校准需手动 | 无自动测量与持续反馈，广色域/HDR 支持参差 |
| **彩谱、远方等国内厂商** | **测量硬件强**（分光测色仪、色差仪），价格优势明显 | 强在"测—比"，软件闭环与云端协同弱 | 软件生态、自动化闭环、云端供应链协同与国际厂商有差距 |

### 2.4 机会定位

**与国内测量硬件厂商互补，做"硬件测量 + AI 云端校正闭环"的协同层，避免正面竞争。**

- 国内厂商（彩谱、远方等）在测量硬件上已具竞争力，但软件闭环、自动化校正、云端协同是短板。
- 本产品以配套硬件（或兼容第三方硬件）做测量输入，以 AI 云端/本地引擎做"智能校正 + 闭环验证 + 归因"的闭环输出，形成差异化。
- 不追求替代 ICC 体系，而是以 ICC 为物理底座，用 AI 补足非线性与感知优化，构建混合架构。

## 3. 产品目标与范围

### 3.1 产品目标（量化指标）

| 指标 | 目标值（参考） |
|---|---|
| 标定自动化率 | ≥ 95% 的色卡标定可通过"拍照即完成"，无需人工布点 |
| ΔE 达标率 | 闭环迭代后，目标色 ΔE00 ≤ 容差（默认 ≤ 2.0）的达标率 ≥ 90% |
| 校验迭代次数 | 闭环自动迭代，平均收敛步数 ≤ 3 步（不含首测） |
| 支持设备数 | MVP 支持 ≥ 5 类显示设备，平台期支持 ≥ 50 类 |
| 支持色卡数 | MVP 支持 ≥ 3 种标准色卡（ColorChecker、ColorChecker SG、Macbeth），平台期可扩展 |
| 测量条件异常检出率 | ≥ 90% 的异常测量条件可自动识别并提示重测 |

### 3.2 功能范围（9 大模块）

1. 设备管理
2. 测量与采集
3. 色卡识别与标定（AI）
4. 色彩转换与匹配
5. 智能校正 / Profile 生成（AI）
6. ΔE 检测与判定
7. 闭环验证与迭代（AI）
8. 色域可视化与分析
9. 工作流与任务管理

（详见第 5 章功能需求）

### 3.3 非功能目标

- **精度**：ΔE 计算与 CIEDE2000 标准公式一致；profile 生成精度满足工业验收。
- **性能**：批量处理支持并发，单次色卡识别推理延迟 ≤ 2s（服务端），端侧推理 ≤ 5s。
- **兼容**：支持 Windows / macOS / Linux；支持主流显示设备、印刷设备、相机。
- **安全**：测量数据与用户数据加密存储与传输，支持多租户隔离。
- **可扩展**：场景插件化，新场景（如纺织、影视）以插件形式接入，不改动核心引擎。

## 4. 用户角色与典型场景

### 4.1 用户角色

| 角色 | 职责 | 使用模块 |
|---|---|---|
| 设计师 | 创建/输出设计稿，保证跨设备一致 | 设备管理、色域可视化、色彩转换、闭环验证 |
| 摄影师 | 相机标定、拍摄色彩还原 | 测量采集、色卡识别标定、ΔE 检测 |
| 印刷工程师 | 打样校色、印张检测、校正回传 | 测量采集、智能校正、闭环验证、工作流 |
| 质检员 | 批次色差判定、异常检测 | ΔE 检测、测量采集、工作流 |
| 电商运营 | 商品图色差控制、跨端一致性 | 色卡识别、ΔE 检测、闭环验证 |
| 系统管理员 | 设备注册、权限管理、数据维护 | 设备管理、工作流管理、权限 |

### 4.2 典型场景（映射闭环环节）

**场景 A：显示器一键校准**
设计师连接配套色度计 → 系统自动识别设备并采集测量 → AI 生成校正 profile/LUT → 回写设备 → 自动复测验证 ΔE → 达标则闭环完成，不达标自动迭代。
→ 覆盖：测量采集 → 智能校正 → 闭环验证 → 迭代

**场景 B：印刷打样校色**
印刷工程师对打样稿测色 → 系统比对标准样计算 ΔE00 → 判定是否达标 → 不达标则 AI 生成墨量补偿建议 → 调整后复测 → 直至达标。
→ 覆盖：测量采集 → ΔE 检测 → 智能校正 → 闭环验证

**场景 C：电商商品图色差检测**
运营上传商品图与实物测量数据 → 系统自动识别色卡/标定 → 计算图实物 ΔE → 定位超限区域 → 归因分析（拍摄/修图/展示环节）→ 输出报告。
→ 覆盖：色卡识别 → ΔE 检测 → 归因分析

**场景 D：相机色彩标定**
摄影师在拍摄现场拍色卡 → AI 自动检测色块、读数、生成相机专属 ICC profile → 后续拍摄自动应用，保证色彩还原。
→ 覆盖：测量采集 → 色卡识别标定

**场景 E：批量校色任务**
管理员对产线/工作室多台设备批量下发校色任务 → 系统并行采集、校正、验证 → 汇总报告 → 异常设备自动标记重测。
→ 覆盖：工作流管理 → 全闭环各环节

## 5. 功能需求

### 5.1 设备管理

| 功能 | 描述 |
|---|---|
| 设备注册 | 登记显示器、打印机、相机、测量设备等，记录设备型号、色域、ICC profile。 |
| Profile 录入 | 支持导入/自动生成 ICC profile，关联到具体设备。 |
| 设备分组 | 按场景/部门/产线分组管理，便于批量操作。 |
| 状态监控 | 监控设备校准状态、profile 有效期、硬件连接状态。 |
| 硬件连接管理 | 管理配套测量硬件的连接、固件升级、设备识别。 |

### 5.2 测量与采集

| 功能 | 描述 |
|---|---|
| 数据采集 | 对接色度计、分光光度计、相机，采集色彩测量数据（RGB/XYZ/Lab/光谱）。 |
| 测量条件自适应校验 | **AI 能力**：自动判断测量条件是否合格（光照均匀性、色卡完整性、设备色域覆盖），识别异常。 |
| 异常检测与重测提示 | 测量数据异常时自动提示重测，避免错误数据流入校正环节。 |
| 测量点规划 | 自动规划测量布点，减少人工操作。 |

### 5.3 色卡识别与标定（AI）

| 功能 | 描述 |
|---|---|
| 自动色卡检测 | **AI 能力**：用视觉模型（YOLO 等）检测图像中的色卡，定位色块位置与数量。 |
| 色块读数 | **AI 能力**：读取各色块像素值，与已知参考值比对，计算校正矩阵。 |
| Profile 自动生成 | 基于读数生成相机/设备专属 ICC profile，"拍照即完成标定"。 |
| 标定向导 | 引导用户拍摄，实时反馈拍摄质量（角度、光照、遮挡）。 |

### 5.4 色彩转换与匹配

| 功能 | 描述 |
|---|---|
| ICC 转换 | 基于 lcms2 引擎，按 ICC profile + 渲染意图执行跨设备色彩转换。 |
| 渲染意图选择 | 支持四类渲染意图，AI 辅助推荐最佳渲染意图。 |
| 色域映射 | 支持色域外颜色的智能映射，含 **AI 优化的感知映射**（宽色域/HDR 下减少色相失真）。 |
| 跨设备匹配 | 支持设备间色彩匹配，AI 补足非线性映射部分。 |

### 5.5 智能校正 / Profile 生成（AI）

| 功能 | 描述 |
|---|---|
| 校正矩阵生成 | **AI 能力**：基于测量数据学习设备色彩特性，生成/优化校正矩阵。 |
| Profile 智能生成 | **AI 能力**：生成更优的 ICC profile，ICC 为骨架，神经网络补非线性。 |
| 跨设备匹配校正 | 支持多设备跨设备匹配与校正，减少每设备单独建模成本。 |
| 校正参数输出 | 输出显示器 LUT、印刷墨量补偿、染料配方建议、设计稿修正等参数。 |

### 5.6 ΔE 检测与判定

| 功能 | 描述 |
|---|---|
| 色差计算 | 基于 CIEDE2000（及 ΔE\*ab、ΔEcmc）计算目标色与实测色的色差。 |
| 标准样比对 | 与标准样比对，支持自定义容差阈值。 |
| Pass/Fail 判定 | 按容差自动判定合格/不合格。 |
| 色差区域定位 | 定位图像中 ΔE 超限的区域，可视化展示。 |
| 色差归因分析 | **AI 能力**：自动诊断色差来源（设备、材料、流程、测量条件），给出根因。 |

### 5.7 闭环验证与迭代（AI）

| 功能 | 描述 |
|---|---|
| 校正后 ΔE 预测 | **AI 能力**：预测校正后色差，提前判断是否达标，避免无效校正。 |
| 超限定位与修正建议 | 自动定位超限区域，给出迭代修正建议。 |
| 自动迭代循环 | **AI 能力**：校正→验证→再校正，自动迭代直至 ΔE 达标，无需人工介入循环。 |
| 闭环状态追踪 | 记录每次迭代的 ΔE、参数、耗时，追踪闭环收敛过程。 |

### 5.8 色域可视化与分析

| 功能 | 描述 |
|---|---|
| CIE 1931 色度图 | 渲染 CIE 1931 色度图，叠加设备色域边界。 |
| 色域覆盖图 | 对比多设备/多色彩空间的色域覆盖，直观展示覆盖范围。 |
| ΔE 分布可视化 | 以色差分布图展示 ΔE 分布，支持交互分析。 |
| 色彩对比 | 支持色彩并排对比、差异高亮。 |

### 5.9 工作流与任务管理

| 功能 | 描述 |
|---|---|
| 任务编排 | 编排批量校色、批量检测等任务，支持定时与触发。 |
| 历史记录 | 记录每次测量、校正、验证的历史，可追溯。 |
| 报告导出 | 生成色彩管理报告，支持 PDF/Excel 导出。 |
| 权限与多租户 | 支持角色权限与多租户隔离，满足企业合规。 |

## 6. 非功能需求

### 6.1 精度指标
- ΔE 计算与 CIEDE2000 标准公式一致，误差可忽略。
- profile 生成精度满足工业验收标准（如印刷 ISO 12647、G7 相关要求）。
- AI 校正精度在宽色域/HDR 场景下优于纯 ICC 传统算法（以 ΔE 衡量）。

### 6.2 性能指标
- 单次色卡识别推理延迟：服务端 ≤ 2s，端侧 ≤ 5s。
- 批量处理：支持 ≥ 50 台设备并发校色，吞吐量可水平扩展。
- 色彩转换：单张图像转换延迟 ≤ 100ms（服务端）。

### 6.3 可用性
- 闭环流程向导化，非专业用户可独立完成标定与校准。
- 异常操作有明确提示与引导。

### 6.4 兼容性
- 操作系统：Windows / macOS / Linux。
- 设备：主流显示设备、印刷设备、相机；配套测量硬件跨平台驱动。
- 文件格式：ICC/ICM profile、常见图像格式、LUT 格式（.cube 等）。

### 6.5 数据安全与隐私
- 测量数据、用户数据加密存储与传输（TLS）。
- 多租户数据隔离。
- 支持私有化部署，数据本地化。

### 6.6 可扩展性
- 场景插件化：新场景（纺织、影视、产线）以插件接入，不改核心引擎。
- 算法引擎可插拔：传统算法与 AI 算法可切换或混合。

## 7. 硬件方案

### 7.1 配套测量硬件选型建议

| 层级 | 硬件配置 | 面向用户 | 用途 |
|---|---|---|---|
| **入门** | 色度计 + 标准色卡（ColorChecker 等） | 设计师、摄影师、电商 | 显示校准、相机标定、商品图色差检测 |
| **专业** | 分光光度计（台式/便携） | 印刷工程师、质检员 | 印刷打样校色、纺织印染测色、光谱级精度 |
| **产线** | 在线检测设备（相机 + 光谱仪） | 工厂、产线品质 | 产线色彩一致性实时监控、在线 ΔE 判定 |

### 7.2 硬件与软件分工边界

- **硬件负责测量**：物理色彩数据采集（色度、光谱、图像），保证测量精度与物理可靠性。
- **软件负责闭环**：色卡识别、智能校正、ΔE 预测、闭环迭代、归因分析，形成自动反馈。
- **协同原则**：硬件测量是输入，软件校正闭环是输出；同色异谱、面板个体差异、背光老化等物理问题，由"软件校正 + 硬件执行（如 3D LUT）"协同解决，不追求纯软件消除。

### 7.3 硬件生态策略
- 优先自研配套入门级测量硬件，保证体验闭环。
- 同时提供**第三方硬件适配接口**，兼容彩谱、远方等国内厂商测量设备，扩大生态。

## 10. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| **数据稀缺** | 跨设备、跨材质标准化配对数据稀缺，测量成本高 | 以色卡实拍 + ICC profile + 合成数据（模拟色差/变换生成配对）为主，优先在封闭场景积累真实数据，避免一开始追求跨设备通用大模型。 |
| **硬件协议私有** | 各厂商色度计/分光光度计 USB 协议私有，无统一标准 | 基于 pyserial/pyusb 自研设备适配层，按设备文档逐一适配；优先自研配套硬件保证体验，第三方硬件做适配接口。 |
| **物理问题不可纯软件解决** | 同色异谱、面板个体差异、背光老化、环境光影响 | 采用"软件校正 + 硬件执行"协同；明确产品边界，不承诺纯软件消除物理问题。 |
| **精度验证** | AI 校正精度需严格验证，黑箱模型难被工业标准采纳 | 采用混合架构（ICC 物理先验 + AI 补非线性），保留可解释结构；以 ΔE 量化验证，对标行业标准。 |
| **成本** | 软硬件一体研发与供应链成本高 | 分层硬件策略，入门硬件控制成本；软件订阅摊薄硬件成本；优先软件闭环价值，硬件按需扩展。 |
| **与现有生态兼容** | AI 模型需与 ICC 生态兼容，避免落地障碍 | 以 ICC 为骨架，AI 作为增强层，不做纯替代；保证 profile/LUT 标准格式输出，兼容现有工具链。 |

## 附录 A · V0.2 修订：印前配方预测转型（2026-11）

V0.1 验证闭环算法底座后，产品定位根据实际业务**收敛为面向印前的色彩管理小软件**，
V0.2 已交付并验证。本附录记录定位与范围的修订，供后续版本对齐。

### A1. 核心业务纠偏

1. **数据链路以数值为中心，不需要拍照/色卡上传**：测量数据来自分光光度计等仪器，
   以 LAB 数值录入；V0.1 的色卡拍照识别降级为保留能力（不作为主线）。
2. **旗舰能力 = LAB→CMYK 配方反查**：利用工艺 ICC 数据，将目标 LAB（客户色样）
   反查为最优墨量配方；一次反查包含大量正向预测迭代（粗查表 8.3 万点 + 局部精搜），
   ΔE2000 收敛后输出 C/M/Y/K 百分比。
3. **工艺是一等实体**：工艺（打印机+纸张+墨水组合）绑定专属 ICC 特性文件，
   不同工艺的 ICC 不一样；配方预测、印前转换均以工艺为上下文。
4. **实测验证闭环**：配方打印 → 分光光度计实测 LAB 回填 → 模型误差补偿
   （p' = t - (m - p)）→ 修正配方，迭代至达标。

### A2. V0.2 交付范围（已实现）

| 模块 | 内容 | 状态 |
|---|---|---|
| 工艺库 | 工艺 CRUD、ICC 上传/下载、元数据解析、CIE 色域采样 | ✅ |
| 配方预测 | 批量 LAB→CMYK 反查引擎（迭代轨迹/预测数）、CSV 批量导入、结果导出 | ✅ |
| 实测验证 | 实测 LAB 回填、误差补偿修正配方、闭环改善判定 | ✅ |
| 印前转换 | 文件预检（嵌入 ICC/模式/DPI/主导色+建议）、经工艺 ICC 转换、软打样预览、CMYK TIFF 输出 | ✅ |
| 工具箱 | CMYK→LAB 正查、LAB ΔE 对比、色域对比、色彩转换器 | ✅ |
| UI 重构 | iOS 扁平风 SPA（侧边栏/底部标签、大标题、渐进式披露）、亮/暗主题、流程阶段锁定 | ✅ |

验证基线：pytest 19 项通过；HTTP 端到端 19 项通过；浏览器视觉验收（亮/暗）通过。
