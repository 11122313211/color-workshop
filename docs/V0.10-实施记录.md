## 4. 护照语义

### 4.1 状态优先级

读取时动态判定，不写入快照：

1. `invalid`：ICC 缺失/不可读；
2. `stale`：当前 ICC、补偿指纹或校准轮次指纹与快照不一致；
3. `incomplete`：无 verified 测量，或 CMYK 工艺无校准轮次；
4. `valid`：不满足以上条件。

“未生成护照”是 API/UI 的 404/空状态，不是第五种状态。

### 4.2 哈希与版本

- `passport_hash`：规范化 JSON 的 sha256；
- 规范化：稳定键序、紧凑分隔、浮点固定 **4 位小数**、`allow_nan=False`；
- 数值等价：整数 `1` 与浮点 `1.0` 规范化为同一表示，避免类型漂移产生伪版本；
- 排除：`generated_at`、`version`、`passport_hash`、`status`、`status_reasons`、`id`；
- 内容不变重复 POST 幂等（`created=false`），不新增版本；
- 历史版本不可变；每工艺最多 50 版，达到上限裁剪最旧版本；
- 版本创建使用模块级写锁串行化；8 线程并发生成测试最终得到连续 `v1–v8`，无重复/丢版；
- 测试：连续 55 次生成只保留 `v6–v55`（50 版）。

### 4.3 签样门禁

- 护照不嵌入签样状态，避免循环依赖；
- 签样快照保存 `passport_id/passport_hash/passport_version`；
- 新签样仅允许关联 `valid` 护照；非 valid 关联返回 422；
- `gate` 含护照 hash 时对比当前最新护照：
  - hash 一致且动态状态为 `valid` → allowed；
  - 不一致/旧版本 → `passport_changed`；
  - hash 一致但状态为 `incomplete/stale/invalid` → `passport_incomplete` /
    `passport_stale` / `passport_invalid`；
- legacy 签样没有护照字段时继续按 ICC 指纹判定；
- `release_manifest` 仅在门禁 allowed 时输出护照摘要；护照变化或状态失效后 409。

## 5. 光谱 / 同色异谱

- 条件：`D50`、`D65`、`A`、`FL11`，均为 2°；界面显示 `CIE F11`；
- 复用 `cgats.integrate_lab` / `white_xyz`；
- 输入行限定 `380–730nm`（与下游 CGATS 积分网格一致），`conditions=[]` 返回 422；
- 输出：各条件两组 Lab、ΔE00、最大 ΔE、最差光源、风险等级与 warnings；
- 阈值：

| 最大 ΔE00 | 等级 |
|---|---|
| `≤1.0` | `low` |
| `≤2.0` | `medium` |
| `>2.0` | `high` |

- OBA 反射率 >1 合法、不裁切；<0 或 >1.5 给 warning；
- 积分/Lab/ΔE 出现非有限值（如超大反射率）返回 422，不输出 `null`；
- 不同波长网格各自独立积分，不重采样；
- 无光谱：`available=false` + warning，不伪造曲线/ΔE；
- 双会话按 patch label 匹配，返回 top 差异及两组光谱；
- 常显：“工程同色异谱风险指标，不等同 CIE 15 特殊同色异谱指数 MI”。

## 8. 已知限制

- 存储仍为 JSON，不使用数据库；护照写入使用进程内锁，多进程/多 worker 部署需外置文件锁或数据库事务；
- 护照只导出 JSON/Markdown，不生成 PDF 文件；
- 风险阈值固定 1.0/2.0，无 UI 配置；
- E2E 创建工艺依赖 Windows 系统 ICC `RSWOP.icm`，跨平台需自备兼容 ICC；
- 护照版本历史只有 API，未实现独立 UI 历史列表；
- 光谱双曲线当前以颜色 + 文字图例区分，并附 Lab/ΔE00 表；线型/标记待补；
- `passport_changed` 未使用 `role=alert`/`aria-live`；
- 模态已有焦点圈闭/ESC/焦点恢复，但缺 `aria-labelledby`/背景 `inert`；
- 完整 200% 缩放与屏幕阅读器审计未完成；
- 375px 光谱 top 差异表仍为紧凑表格，纵向卡片化待补；
- 未训练模型、未实现基础油墨 KM 调墨。
